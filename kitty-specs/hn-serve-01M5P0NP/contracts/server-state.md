# Contract: server state on disk

Server state belongs to the server's Unix user and lives under that user's home directory. `hn serve` writes only inside `$HOME/.hn-serve/` and to `$HOME/.ssh/authorized_keys` (NFR-004). The acceptance test for NFR-004 records every path in the server home before and after a full run and fails on any write outside these locations.

## Layout

```text
$HOME/
├── .ssh/                       0700, created if absent
│   └── authorized_keys         0600; managed block plus administrator lines
└── .hn-serve/                  0700
    ├── hooks/                  0700, regenerated by every administration command
    │   ├── pre-receive         0700 script: exec ABS_HN serve hook pre-receive
    │   └── post-receive        0700 script: exec ABS_HN serve hook post-receive
    ├── repositories/           0700
    │   └── NAME.git/           bare repository created by hn serve repo create
    └── state/                  0700
        ├── registry.json       0600
        ├── tmp/                0700, TMPDIR for Git and hooks
        └── repos/              0700
            └── NAME/           0700
                ├── config.json     0600
                ├── branches.json   0600, absent until the first owned branch
                ├── push.log        0600, append-only JSON Lines
                ├── lock            0600, flock target for pushes
                ├── lfs.lock        0600, flock target for LFS commits
                └── lfs/            0700
                    ├── incoming/   0700, staged uploads
                    └── objects/    0700, verified objects in OID[0:2]/OID[2:4]/OID
```

Validation runs at the start of every `hn serve` command. Any of the following is a fail-closed defect that stops the command with a message naming the path: a symlink anywhere in the layout, a directory that is not 0700, a state file that is not 0600, a hook script whose bytes differ from the generated content, an entry in `state/`, `state/repos/` or `state/repos/NAME/` that the layout does not define, a `state/repos/NAME/` without a matching `repositories/NAME.git/` or the reverse, and a JSON file with unknown fields, trailing data, or a size above 16 MiB (64 MiB for `push.log`, which is read only by tests and operators). Directories and files are created through `ensurePrivateDirectory` and `writePrivateFileAtomic`.

## registry.json

```json
{
  "version": 1,
  "keys": [
    {
      "fingerprint": "SHA256:Jd8bC8QWw0m0Y4l6m6yZ1gq5q3o9s0Kc2b2f4QwA9eU",
      "publicKey": "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIExampleOnlyNotARealKeyxxxxxxxxxxxxxxxxxxxxx",
      "actor": "4f1c9a6d0d2b7e3a8c5f6e1b9d0a7c3e2f4b6d8a0c1e3f5a7b9d1c3e5f7a9b1c",
      "added": "2026-10-24T20:00:00Z"
    }
  ]
}
```

Keys are sorted by fingerprint. The fingerprint is `SHA256:` followed by the unpadded standard base64 encoding of the SHA-256 digest of the decoded key blob, which is the format `ssh-keygen -l -E sha256` prints. A registry that does not exist is an empty registry; any other read error is fatal.

## config.json

```json
{
  "version": 1,
  "name": "rust-pingpong",
  "protected": ["refs/heads/main"],
  "lfsQuotaBytes": 1073741824,
  "budgets": {
    "maxEvents": 10000,
    "maxObjects": 100000,
    "maxObjectBytes": 67108864,
    "maxAttachmentBytes": 16777216,
    "maxTotalBytes": 1073741824
  }
}
```

`budgets` uses the field names and validation of `ReplicationBudgets` in `replication.go`.

## branches.json

```json
{
  "version": 1,
  "branches": [
    {"ref": "refs/heads/feature/a", "owner": "<64-hex actor>", "created": "2026-10-24T20:05:00Z"}
  ]
}
```

Sorted by `ref`. Written only by `post-receive` while the repository lock is held.

## push.log

One JSON object per line, appended with `O_APPEND` under the repository lock:

```json
{"time":"2026-10-24T20:06:00Z","actor":"<64-hex>","key":"SHA256:...","verdict":"rejected","updates":[{"ref":"refs/heads/main","old":"<oid>","new":"<oid>"}],"codes":["protected-no-proposal"]}
```

## Managed authorized_keys block

`hn serve` owns the lines between the two marker lines, inclusive. Lines outside the block are preserved byte for byte, including their line endings and a missing final newline. When no block exists, the block is appended after the existing content, preceded by a newline if the file does not end with one. The file is replaced atomically.

```text
# BEGIN hn serve managed keys; edit with hn serve key
restrict,command="/usr/local/bin/hn serve git --key SHA256:Jd8bC8QWw0m0Y4l6m6yZ1gq5q3o9s0Kc2b2f4QwA9eU" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIExampleOnlyNotARealKeyxxxxxxxxxxxxxxxxxxxxx hn-serve:4f1c9a6d0d2b
# END hn serve managed keys
```

One line per binding, sorted by fingerprint. The comment is `hn-serve:` plus the first 12 characters of the actor. The command path is the absolute, symlink-resolved path of the `hn` executable that wrote the block, and the write is refused when that path contains a double quote, backslash or whitespace. Duplicate begin or end markers, an end marker without a begin marker, an `authorized_keys` that is a symlink, not a regular file, or writable by group or others, and a `.ssh` directory that is a symlink or writable by group or others are defects that stop the command.

## Marker ref

`refs/hn/serve/v1` points at the blob with exact content `hn-serve/1\n` (11 bytes) in the repository's object format. Only `hn serve repo create` writes it; every push that names it is refused with `reserved-ref`.
